Radio Component Documentation

The Radio component styles a native input[type="radio"] with a custom circle and inner dot. It uses fx-radio-frame as wrapper, with the input and a label[for]. Options in the same group share the same name. Supports checked, focus-visible, disabled, readonly, invalid, and valid states.

Base usage

<div class="fx-radio-frame">
  <input id="r-a" type="radio" class="fx-radio" name="group" />
  <label for="r-a">Option A</label>
</div>
<div class="fx-radio-frame">
  <input id="r-b" type="radio" class="fx-radio" name="group" checked />
  <label for="r-b">Option B</label>
</div>
  • Use the same name on all radios in a group so only one can be selected.

Checked and unchecked

<input type="radio" class="fx-radio" name="g" />
<input type="radio" class="fx-radio" name="g" checked />
  • Checked state uses --fx-radio-checked-color for the ring and inner dot.

Focus-visible

<input type="radio" class="fx-radio" name="g" />
<label for="...">Focus me</label>
  • Focus ring on the circle uses --fx-focus-ring-outline-width, --fx-focus-ring-color, --fx-focus-ring-outline-offset.

Disabled state

<input type="radio" class="fx-radio" name="g" disabled />
<input type="radio" class="fx-radio" name="g" disabled checked />
  • Label and circle use muted color and --fx-disabled-control-opacity.

Readonly state

<input type="radio" class="fx-radio" name="g" readonly checked />
  • readonly disables pointer events so the value cannot be changed by click; use when the value is display-only or controlled elsewhere.

Validation states (invalid / valid)

<input type="radio" class="fx-radio" name="g" invalid />
<input type="radio" class="fx-radio" name="g" valid checked />

<!-- Invalid and disabled together -->
<input type="radio" class="fx-radio" name="g" invalid disabled />
<input type="radio" class="fx-radio" name="g" invalid disabled checked />
  • Set invalid or valid (e.g. via JS after validation). Uses --fx-invalid-border-color, --fx-invalid-color, --fx-valid-border-color, --fx-valid-color.
  • When both invalid and disabled are set, the result combines invalid border/color with disabled opacity, cursor, and non-interactivity (see the two examples above).

Quick customization

<div class="fx-radio-frame" style="--fx-radio-size: 1.25rem;">...</div>
<div class="fx-radio-frame" style="--fx-radio-size: 2rem; --fx-radio-dot-space: 0.4rem;">...</div>
  • --fx-radio-size circle size
  • --fx-radio-dot-space gap between ring and inner dot
  • --fx-radio-checked-color ring and dot color when checked
  • --fx-border-width, --fx-border-color, --fx-control-background-color
  • --fx-focus-ring-* focus outline
  • --fx-control-padding-x gap between circle and label
  • --fx-text-color, --fx-text-muted-color, --fx-disabled-control-opacity
  • --fx-transition animation

What the CSS package covers

  • Frame: .fx-radio-frame — wrapper with margin: 0 and layout for input + label.
  • Input: input[type="radio"].fx-radio — visually hidden (clip, opacity), positioned for accessibility.
  • Label: label[for] — cursor, font, color, padding; ::before = custom circle (size, border, background, border-radius 50%); ::after = inner dot (visible when checked).
  • Checked: :checked + label::before border color; :checked + label::after opacity and scale for the dot.
  • Focus: :focus-visible:not(:disabled) + label::before — outline and offset.
  • Disabled: label color/opacity/cursor/pointer-events; circle and dot use muted color and opacity.
  • Readonly: [readonly] — pointer-events none on input and label.
  • Invalid/Valid: [invalid] and [valid] — label color, circle border, and when checked dot color.

Accessibility notes

  • Always use a label[for] that matches the input id so the radio is properly associated and clickable.
  • Use the same name for all options in a group so the selection is mutually exclusive and keyboard navigation works.
  • The native input is visually hidden but remains focusable and announced by screen readers; the custom circle is purely visual.
  • For validation, set invalid/valid in sync with aria-invalid and provide error/success messages for screen readers.
